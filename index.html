Think of your project as a story. Every commit saves a snapshot, and a branch gives you a safe place to write the next chapter.

That’s really all a branch is: a lightweight, movable name for a line of work. It lets you try something new without changing the version everyone else is using.

A simple mental model

Imagine you’re writing a shared cookbook. The main branch is the trusted edition. You want to add a dessert recipe, but you don’t want half-finished notes appearing in the book just yet.

Your own copy, same story so far

Make a branch and you start from the latest commit. Your new work moves forward independently; the main branch stays just as it was.

In the graph above, each dot is a saved commit. The line is the history connecting them. A branch name like feature simply points to the latest commit on that line.

Why branches help

Branches make it easy to experiment without putting unfinished work in the way. You can build a feature, fix a bug, or test a risky idea while the stable version remains untouched.

01
Work independently

Your commits stay on your branch while you make progress. Other branches don’t move when you save a commit.

02
Share it for feedback

Push the branch and open a pull request. Teammates can review your changes before they become part of the shared version.

03
Bring it together

When the work is ready, merge the branch. Git joins its changes into the destination branch’s history.

Make and merge a branch

Here’s a typical small workflow. The first command creates a branch and switches to it; commits you make next belong to that branch.

Terminal · a small feature workflow
# Start a branch and move onto it
$ git switch -c add-dessert

# Save your changes on this branch
$ git add .
$ git commit -m "Add dessert recipe"

# When it’s ready, bring it into main
$ git switch main
$ git merge add-dessert

If two branches change the same part of a file in different ways, Git may ask you to resolve a merge conflict. That’s normal: choose how the combined result should look, save it, and finish the merge.

“Branching isn’t copying your whole project. It’s giving your next change its own path.”

The thing to remember

Branches are cheap, so make them whenever you want a separate line of work. Commit as you go, then merge when your changes are ready to join the shared story.

In one sentence

A Git branch is an independent pointer to a commit—use one to work safely, and merge it to bring the finished changes back.
